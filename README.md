# LifeOS — المرحلة الأولى

واجهة شخصية عربية RTL لإدارة المهام والمشاريع والمواعيد، مبنية باستخدام React وTypeScript وVite، مع دعم PWA وقابلية ربط Supabase.

> هذه نسخة أولية قابلة للتشغيل، وليست نظامًا إنتاجيًا مكتملًا. في وضع المعاينة تُحفظ بيانات تجريبية في `localStorage` على المتصفح الحالي. بعد إعداد Supabase، يلزم تسجيل الدخول وتُحفظ البيانات في قاعدة البيانات.

## المتطلبات

- Node.js 20 أو أحدث، مع npm.
- حساب Supabase عند الرغبة في استخدام التخزين السحابي وتسجيل الدخول.
- Git اختياري للنشر.

## التشغيل محليًا

```bash
npm install
npm run dev
```

افتح عنوان Vite المحلي الذي يظهر في الطرفية. من دون متغيرات Supabase سيعمل التطبيق في وضع المعاينة، وستبقى بيانات المعاينة على المتصفح نفسه.

## إعداد Supabase

1. أنشئ مشروع Supabase جديدًا مستقلًا عن مشروع `shifts`.
2. افتح SQL Editor في لوحة Supabase.
3. نفّذ محتوى `supabase/migrations/202610300001_initial_lifeos.sql`.
4. من إعدادات المشروع انسخ Project URL وPublishable key (أو anon key المتوافق مع مشروعك).
5. انسخ `.env.example` إلى ملف `.env.local` واملأ القيم:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
```

6. أعد تشغيل خادم التطوير.
7. أنشئ مستخدمًا من لوحة Supabase Auth، ثم سجّل الدخول من LifeOS. لا يوجد تسجيل عام في هذه النسخة.

**أمان:** لا تضع `service_role` أو Secret API key في `.env.local` الخاص بالواجهة أو في GitHub. مفاتيح الواجهة العامة لا تغني عن سياسات RLS. فعّل التحقق من البريد وسياسات كلمات المرور المناسبة في إعدادات Auth.

## الوظائف الموجودة

- لوحة رئيسية بإحصاءات المهام والمشاريع والمواعيد.
- إنشاء المهام وتغييرها بين مفتوحة ومكتملة.
- إنشاء المشاريع وعرض تقدمها بناءً على المهام المرتبطة بها.
- إنشاء المواعيد وعرض قائمة الأحداث القادمة.
- بحث نصي مبسط.
- واجهة RTL متجاوبة مع الموبايل والتابلت.
- PWA manifest وتخزين ملفات الواجهة الثابتة للتشغيل المتكرر.

## اختبار يدوي مقترح

### وضع المعاينة

1. شغّل التطبيق من دون إعداد `.env.local`.
2. أنشئ مشروعًا جديدًا.
3. أضف مهمة واربطها بالمشروع.
4. أنجز المهمة وتحقق من تحديث نسبة تقدم المشروع.
5. أضف موعدًا وتأكد من ظهوره في الرئيسية والتقويم.
6. حدّث الصفحة وتحقق من بقاء البيانات على المتصفح نفسه.

### وضع Supabase

1. أنشئ مستخدمًا من لوحة Auth.
2. سجّل الدخول في LifeOS.
3. أنشئ مشروعًا ومهمة وموعدًا.
4. تحقق من ظهور السجلات في الجداول مع `user_id` الصحيح.
5. اختبر بحساب مستخدم ثانٍ إن توفر: يجب ألا يستطيع قراءة أو تعديل بيانات الحساب الأول بسبب RLS.
6. اختبر تسجيل الخروج ثم تسجيل الدخول مجددًا.

## النشر

### Vercel

- ارفع المجلد إلى مستودع GitHub.
- استورد المستودع في Vercel.
- Build command: `npm run build`
- Output directory: `dist`
- أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` إلى Environment Variables.
- انشر، ثم أضف عنوان الموقع إلى إعدادات Redirect URLs في Supabase Auth عند الحاجة.

### ملاحظات PWA

- تثبيت PWA يتطلب HTTPS في النشر، أو localhost أثناء التطوير.
- تخزين الواجهة مؤقتًا لا يعني أن عمليات قاعدة البيانات تعمل دون إنترنت.
- إشعارات الخلفية والتذكيرات الدقيقة ليست ضمن هذه المرحلة.

## نطاق المرحلة الأولى وحدودها

- التقويم حاليًا قائمة أحداث مرتبة بالتاريخ، وليس شبكة شهرية كاملة.
- لا توجد عمليات حذف أو تحرير للسجلات من الواجهة بعد.
- بيانات المعاينة ليست مزامنة سحابية ولا نسخة احتياطية.
- واجهة تسجيل الدخول تستخدم كلمة مرور؛ إنشاء المستخدمين وإدارة الوصول تتم من Supabase Auth.
- إضافة مجالات الشغل والمال والصحة والأسرة مؤجلة للمراحل التالية.
